# Routebook — REST API на Express

Модульный Express API для пользователей и статей: CRUD, Map-коллекции, проверка данных и обработка ошибок. Интерактивный интерфейс доступен по `/demo/`.

## Запуск

Используйте Node.js 24 (указан в `.nvmrc`); поддерживаемый минимум — 22.12. Откройте папку проекта в VS Code. `code .` необязательна.

```bash
npm install
npm start
```

API: `http://localhost:3000/`. Интерфейс с настоящими HTTP-запросами: `http://localhost:3000/demo/`.

```bash
npm run dev
```

Режим разработки автоматически перезапускает сервер. `PORT` и `HOST` можно задать в `.env` по образцу `.env.example`; по умолчанию `3000` и `127.0.0.1`.

Статическое демо без Express и без установки зависимостей:

```bash
npm run demo
```

Сервер останавливается через Ctrl+C. Исходный HTML не нужно открывать двойным щелчком: используйте локальный сервер. Node.js API и браузерное демо — разные среды выполнения.

## Проверки

```bash
npm run test:native
npm install
npm test
npm run check
npx playwright install chromium
npm run test:browser
npm run test:report
```

`test:native` использует встроенный `node:test` и не требует npm-зависимостей. `npm test` запускает неизменённые тесты задания через Vitest. `check` проверяет синтаксис, JSON, нативные тесты, исходные тесты и сборку, а также настоящий HTTP API. `lint` — синтаксическая проверка Node.js, не ESLint.

`test:browser` запускает Chromium и локальные серверы на свободных портах; проверяет публикацию во вложенном пути `/repository-check/` и отдельно режим настоящего Express API. `test:report` сохраняет реальный вывод Vitest в `reports/test-output.txt`, HTML-отчёт и скриншот `reports/tests.png`. При ошибке тестов команда завершается с ненулевым кодом; отсутствие браузера не скрывает результат тестов.

```bash
npm run test:report -- --native
```

Этот вариант создаёт отдельный отчёт по нативным тестам. Он не заменяет исходные Vitest-тесты.

Первоначально используйте `npm install`: подтверждённого `package-lock.json` в поставке нет. После успешной установки сохраните созданный lockfile в своём репозитории и используйте `npm ci`. Подготовленные папки репозиториев не содержат устаревшего `yarn.lock`. Ветка Vitest 3.x сохранена для совместимости с исходными моками; версия 3.2.7 зафиксирована. Express 5.3.x.

## Сборка и публикация

```bash
npm run build
npm run preview
```

Preview: `http://127.0.0.1:4173/`. Другой порт: `npm run preview -- --port 4174`. Выходные файлы находятся в `dist/`.

GitHub Pages публикует статический интерфейс, а не Node.js-процесс. В статическом режиме коллекции обрабатываются локально той же бизнес-логикой из `src/domain`, без HTTP API. При открытии `/demo/` на сервере Express интерфейс выполняет настоящие запросы; автоматической подмены сбоя API демоданными нет.

Демо после публикации: `https://USERNAME.github.io/REPOSITORY/`. Это шаблон, а не уже опубликованный адрес. Инструкция: [docs/PUBLISHING.md](docs/PUBLISHING.md).
